是不是因为还有之前没处理完的信息呀，究竟怎么回事？

从你的描述和日志信息来看，服务器的资源（如文件描述符）可能未正确释放，导致连接未及时关闭，从而阻塞了新的连接请求。以下几个因素可能是问题的根源：

1. **未释放的文件描述符**：客户端断开时，服务器可能没有正确释放文件描述符，导致服务器的文件描述符资源被耗尽。大批量请求后，服务器已经达到文件描述符上限，导致连接无法建立或操作异常。

2. **连接泄漏**：如果服务器未正确关闭连接资源，可能会在操作系统层面上留下未清理的连接状态，使后续请求受到影响。

3. **客户端阻塞**：客户端代码在发起大量并发请求后，可能有未处理的连接导致的线程阻塞，使客户端新请求等待无法发送或接受完整数据。

### 解决思路

可以从以下几个方面排查并优化代码：

1. **增加连接资源释放逻辑**：
   - 确保 `poll.registry().deregister(client_stream)?;` 调用后，立即移除对应的 `Token`，避免使用到已经无效的 `Token`。
   - 在 `TcpStream` 的生命周期结束时，确保及时关闭资源。

2. **提高操作系统文件描述符限制**：
   - 在 Linux 系统中，可以通过 `ulimit -n 4096` 命令增加文件描述符限制。
   - 确保系统允许足够的并发连接。

3. **增加服务器日志监控，确定问题位置**：
   - 记录 `Token` 的分配和释放情况，确保每个 `Token` 在连接关闭时都被释放。
   - 记录接收数据时的连接状态，观察是否有重复连接。

4. **排查客户端阻塞原因**：
   - 确保客户端每个线程都正确退出，避免未完成请求阻塞主线程。
   - 使用 `threading` 库中的 `setDaemon(True)`，以确保主线程结束后子线程自动释放。

### 改进后的服务器代码
以下改进可以帮助释放资源、提高日志可读性，并尽量避免 `Err(Os { code: 107...` 的报错：

```rust
use std::{
    collections::HashMap,
    io::{self, Read, Write},
    net::SocketAddr,
};
use mio::{Events, Interest, Poll, Token};
use mio::net::{TcpListener, TcpStream};
use crate::base::properties::Properties;

const SERVER: Token = Token(0);

pub fn main() -> io::Result<()> {
    only_epoll()
}

fn only_epoll() -> io::Result<()> {
    let addr: SocketAddr = format!(
        "{}:{}",
        Properties::get("server.ip", "127.0.0.1"),
        Properties::get("server.port", "8090")
    )
    .parse()
    .map_err(|e| io::Error::new(io::ErrorKind::InvalidInput, e))?;

    let mut listener = TcpListener::bind(addr)?;
    println!("服务器正在运行，监听 {}", addr);

    let mut poll = Poll::new()?;
    let mut events = Events::with_capacity(128);
    poll.registry().register(&mut listener, SERVER, Interest::READABLE)?;

    let mut clients = HashMap::new();

    loop {
        poll.poll(&mut events, None)?;

        for event in &events {
            match event.token() {
                SERVER => {
                    match listener.accept() {
                        Ok((mut stream, _)) => {
                            println!("新连接: {:?}", stream.peer_addr());
                            let token = Token(clients.len() + 1);
                            poll.registry().register(&mut stream, token, Interest::READABLE)?;
                            clients.insert(token, stream);
                        }
                        Err(e) => {
                            eprintln!("接受连接时出错: {}", e);
                        }
                    }
                }
                token => {
                    if let Some(client_stream) = clients.get_mut(&token) {
                        let mut buffer = vec![0; 1024];
                        match client_stream.read(&mut buffer) {
                            Ok(0) => {
                                println!("连接已关闭: {:?}", client_stream.peer_addr());
                                poll.registry().deregister(client_stream)?;
                                clients.remove(&token);
                            }
                            Ok(n) => {
                                let message = String::from_utf8_lossy(&buffer[..n]);
                                println!("收到消息: {}", message);
                                if let Err(e) = client_stream.write_all(&buffer[..n]) {
                                    eprintln!("写入失败: {}", e);
                                    poll.registry().deregister(client_stream)?;
                                    clients.remove(&token);
                                }
                            }
                            Err(e) => {
                                eprintln!("读取失败: {}", e);
                                poll.registry().deregister(client_stream)?;
                                clients.remove(&token);
                            }
                        }
                    }
                }
            }
        }
    }
}
```

### 调试建议
1. **客户端和服务器连接数限制**：提高系统文件描述符上限以支持更高并发。
2. **监控客户端阻塞问题**：增加超时机制，确认每个客户端请求完成。
3. **网络监控工具**：如 `netstat` 检查是否存在大量 `TIME_WAIT` 或 `CLOSE_WAIT` 状态连接。
